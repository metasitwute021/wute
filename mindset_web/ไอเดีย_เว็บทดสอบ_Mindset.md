## 1️⃣ แนวคิดหลัก

**"ขอทานที่ให้อะไรกลับ"**

เว็บขอรับบริจาค แต่ไม่ใช่ขอเปล่า — ผู้ใช้จ่ายเงิน (เท่าที่อยากจ่าย) แล้วได้ **รายงานนิสัย/mindset ของตัวเอง** กลับไป

สิ่งที่ทำให้ไม่เหมือนควิซทั่วไปบนเน็ต มี 3 อย่าง:

| ควิซทั่วไป | เว็บนี้ |
|-----------|--------|
| 20 ข้อ เหมือนกันทุกคน | คลังข้อเป็นร้อย **แต่ละคนเจอเส้นทางไม่เหมือนกัน** แตกกิ่งตามคำตอบ |
| วัดจาก "คุณตอบอะไร" | วัดจาก **"คุณทำตัวยังไงตอนทำแบบทดสอบ"** ด้วย — ข้าม, ย้อนกลับมาแก้, ดูคลิปจนจบไหม, ตอบเร็วแค่ไหน |
| คำถามคิดเอง ไม่มีที่มา | ข้อคำถามอิงกรอบจิตวิทยาที่มีงานวิจัยรองรับ (Big Five + Dweck) |

**ประโยคขายของ:** *"เราไม่ได้ดูแค่คำตอบของคุณ เราดูว่าคุณลังเลตรงไหน ข้ามอะไร และกลับมาแก้อะไร"*

### ทางเลือกการเก็บเงิน

| แบบ | ข้อดี | ข้อเสีย |
|-----|------|--------|
| จ่ายก่อนเริ่มทำ | ได้เงินแน่ | คนไม่รู้จักเว็บจะไม่จ่าย conversion ต่ำมาก |
| ทำฟรี → จ่ายเพื่อปลดรายงานฉบับเต็ม | มาตรฐานอุตสาหกรรม (16personalities ใช้) | รู้สึกเหมือนโดนจับเป็นตัวประกันตอนจบ |
| ⭐ **ทำฟรี → เห็นผลย่อฟรี → จ่ายเท่าที่อยากจ่าย (pay-what-you-want)** | ตรงกับคอนเซปต์ "ขอทาน" ที่สุด, ไม่รู้สึกโดนบังคับ, คนที่ประทับใจจ่ายเยอะกว่าราคาตั้ง | รายได้ต่อหัวคาดเดายาก |

## 3️⃣ ฐานทฤษฎีจิตวิทยา

### แกนหลัก 2 ตัว

**A. Big Five / OCEAN** — กรอบบุคลิกภาพที่มีงานวิจัยรองรับมากที่สุดในโลก (ต่างจาก MBTI ที่นิยมแต่ไม่ผ่านมาตรฐานทางวิชาการ)

| แกน | ย่อ | ปลายหนึ่ง ↔ ปลายหนึ่ง |
|-----|----|---------------------|
| Openness | O | ชอบของใหม่/ความคิดนามธรรม ↔ ชอบของคุ้นเคย/รูปธรรม |
| Conscientiousness | C | มีระเบียบ วางแผน ↔ ยืดหยุ่น ไปตามน้ำ |
| Extraversion | E | ได้พลังจากคน ↔ ได้พลังจากการอยู่คนเดียว |
| Agreeableness | A | ประนีประนอม เห็นใจ ↔ ตรงไปตรงมา แข่งขัน |
| Neuroticism | N | อ่อนไหวต่อความเครียด ↔ นิ่ง ไม่หวั่นไหว |

> อ้างอิงชุดข้อคำถามสาธารณะที่ใช้ได้ฟรี: **IPIP** (ipip.ori.org) — public domain, ไม่ต้องจ่ายลิขสิทธิ์ ต่างจาก NEO-PI-R ที่มีลิขสิทธิ์

### ✅ ตรวจลิขสิทธิ์แล้ว (สำคัญ เพราะเว็บนี้จะรับเงิน = ใช้เชิงพาณิชย์)

| เครื่องมือ | สถานะ | ใช้ได้ไหม |
|-----------|-------|----------|
| **IPIP** | Public domain — เจตนาให้ใช้ได้ทั้งงานวิจัย **และเชิงพาณิชย์** ไม่มีค่าธรรมเนียม แปลได้ | ✅ ใช้เป็นแกน Big Five |
| **Dweck — Implicit Theories of Intelligence Scale** | ไม่มีคำประกาศอนุญาตชัดเจน | ⚠️ ไม่ลอกถ้อยคำ — เขียนข้อเองโดยอิงแนวคิด (แนวคิดไม่มีลิขสิทธิ์ ถ้อยคำมี) |
| **Grit Scale (Duckworth)** | ต้องขออนุญาตสำหรับใช้เชิงพาณิชย์ | ❌ ไม่แตะ — วัดความอดทนจากพฤติกรรมแทน |

รายละเอียดทั้งหมดอยู่ใน [`ITEMS.md`](./ITEMS.md)

**B. Growth vs Fixed Mindset (Carol Dweck)** — แกน "mindset" ตรงชื่อเว็บ

- **Fixed:** ความสามารถเป็นของตายตัว → เลี่ยงความท้าทาย, ล้มเหลว = พิสูจน์ว่าไม่เก่ง, ไม่ชอบคำติ
- **Growth:** ความสามารถพัฒนาได้ → เข้าหาความท้าทาย, ล้มเหลว = ข้อมูล, ใช้คำติเป็นวัตถุดิบ

จุดเด่นของเว็บนี้: วัด mindset ได้ **2 ทาง** — จากคำถาม *และ* จากปฏิกิริยาต่อ feedback ที่เว็บยิงใส่ระหว่างทำแบบทดสอบจริง ๆ

### แกนเสริม (วัดจากพฤติกรรมล้วน)

- **ความหุนหัน (impulsivity)** — ตอบเร็วผิดปกติสม่ำเสมอ
- **ความอดทน (persistence)** — ดูคลิป/อ่านจนจบ, ไม่ข้ามข้อยาว
- **ความรอบคอบ/perfectionism** — ย้อนกลับมาแก้ซ้ำ ๆ

### ⚠️ ต้องแยกให้ชัดในเอกสารและในตัวเว็บ

| ส่วน | ความน่าเชื่อถือ |
|------|----------------|
| คะแนนจาก **ข้อคำถาม** ที่ดัดแปลงจาก IPIP / Dweck scale | 🟢 อิงเครื่องมือที่ผ่านการ validate มาแล้ว |
| คะแนนจาก **สัญญาณพฤติกรรม** (ข้าม/ย้อน/เวลา) | 🟡 **เป็นสมมติฐานของเราเอง ยังไม่มีใคร validate** ต้องเก็บข้อมูลพิสูจน์ก่อน |

ข้อนี้สำคัญมาก — ถ้าเอาสัญญาณพฤติกรรมไปคิดคะแนนหนัก ๆ ตั้งแต่วันแรก เว็บจะกลายเป็นหมอดูที่ใส่ศัพท์จิตวิทยา

## 4️⃣ กลไกแตกกิ่ง (Branching Engine)

### หลักการ

- คลังข้อ (item pool): **60–120 ข้อ**
- ผู้ใช้เจอจริง: **15–20 ข้อ**
- ผู้ใช้ 2 คนที่ตอบต่างกัน จะเดินคนละกิ่ง → **เจอข้อไม่เหมือนกัน**

### เลือกข้อถัดไปยังไง — 2 ชั้นซ้อนกัน

**ชั้นที่ 1: เส้นบังคับ (hard edges)** — กำหนดเองสำหรับจังหวะที่มีความหมายทางจิตวิทยา

```
ข้อ 7 ตอบ "ฉันจะเลิกทำ" → บังคับไปข้อ 12 (ตรวจสอบ fixed mindset ให้ลึกขึ้น)
ข้อ 7 ตอบ "ฉันจะลองใหม่"  → บังคับไปข้อ 13 (ตรวจสอบว่าลองใหม่แบบมีแผน หรือแบบดื้อ)
```

**ชั้นที่ 2: เลือกอัตโนมัติแบบ adaptive (IRT-lite)** — ถ้าไม่มีเส้นบังคับ

```
1. ดู ScoreState ปัจจุบัน → หาแกนที่ "ความมั่นใจต่ำสุด" (หลักฐานน้อย หรือคะแนนกลาง ๆ ก้ำกึ่ง)
2. เลือกข้อจาก pool ที่ tag ตรงกับแกนนั้น และยังไม่เคยเจอ
3. ถ้ามีหลายข้อ → เลือกข้อที่ "แยกแยะ" ได้ดีที่สุดที่ระดับคะแนนปัจจุบัน
   (ถ้าคะแนน C สูงอยู่แล้ว อย่าถามข้อที่คนทั่วไปตอบว่าใช่หมด — ไม่ได้ข้อมูลใหม่)
```

นี่คือหลักการเดียวกับ **CAT (Computerized Adaptive Testing)** ที่ข้อสอบอย่าง GRE ใช้ — ต่างกันตรงที่ของเราวัดบุคลิกภาพ ไม่ใช่ความสามารถ

### เงื่อนไขหยุด

หยุดเมื่อ **อย่างใดอย่างหนึ่ง**:
- ครบ 20 ข้อ
- ทุกแกนมั่นใจถึงเกณฑ์แล้ว (จบเร็วกว่า 20 ข้อได้ — และนี่คือฟีเจอร์ ไม่ใช่บั๊ก)
- ผู้ใช้กด "พอแล้ว" เอง (แล้วรายงานต้องบอกตรง ๆ ว่าข้อมูลไม่พอสำหรับแกนไหน)

### กับดักที่ต้องกัน

- 🕳️ **กิ่งตัน** — ทุกเส้นทางต้องมีข้อถัดไปเสมอ ต้องมี fallback pool
- 🔁 **ข้อซ้ำ** — เก็บ set ของ item ที่เจอแล้ว
- 📉 **กิ่งที่สั้นเกินไป** — ถ้าบางเส้นทางจบที่ 8 ข้อ คะแนนจะไม่มีความหมาย ต้องกำหนดขั้นต่ำต่อแกน
- ↩️ **ย้อนกลับไปแก้คำตอบที่แตกกิ่งไปแล้ว** — ถ้าผู้ใช้กลับไปเปลี่ยนคำตอบข้อ 2 ทั้งที่เดินมาถึงข้อ 6 แล้ว จะ *แตกกิ่งใหม่ทั้งหมด* (ซื่อตรงต่อกลไก แต่ลบข้อ 3-6 ที่ทำไปแล้วทิ้ง = ผู้ใช้งง) หรือ *เก็บเส้นทางเดิมไว้* (เดโมเลือกทางนี้ + บันทึกไว้ว่าเปลี่ยน) — ยังไม่ตัดสิน ดูหัวข้อคำถามที่ยังไม่ตอบ
- ⚖️ **กิ่งที่ลำเอียง** — ถ้าตอบแนวหนึ่งแล้วเจอแต่ข้อที่ยืนยันแนวนั้น = confirmation bias ฝังในระบบ ต้องบังคับให้มีข้อ "สวนทาง" ในทุกเส้นทาง

## 5️⃣ สิ่งที่วัดจากพฤติกรรม (Behavioral Telemetry)

> 💡 นี่คือหัวใจของไอเดีย — สิ่งที่เว็บอื่นไม่มี

| สัญญาณ | อาจแปลว่า | ความเชื่อถือ |
|--------|-----------|-------------|
| **กดข้ามข้อ** | หลีกเลี่ยง / ข้อนั้นแตะจุดอ่อน / แค่เบื่อ | 🟡 กลาง — ต้องดูว่าข้ามข้อ tag ไหนบ่อย |
| **ข้ามหลายข้อติดกันตอนท้าย** | หมดความอดทน ไม่ใช่ประเด็นทางบุคลิกภาพ | 🟢 สูง (ตัดสัญญาณนี้ทิ้ง อย่าเอาไปคิดคะแนน) |
| **ย้อนกลับไปดูข้อที่ทำแล้ว** | รอบคอบ (C สูง) **หรือ** ลังเล/กังวล (N สูง) | 🟡 แยกด้วยข้อถัดไป ⬇️ |
| **ย้อนกลับแล้ว "เปลี่ยนคำตอบจริง"** | ถ้าเปลี่ยน = ลังเล/ไม่มั่นใจ, ถ้ากลับไปดูแล้วไม่เปลี่ยน = ตรวจงานตัวเอง (C) | 🟡 กลาง |
| **แก้ข้อเดิมซ้ำ 3+ รอบ** | perfectionism / ความไม่มั่นใจสูง | 🟡 กลาง |
| **เวลาจนแตะครั้งแรก (hesitation)** | สั้นผิดปกติ = หุนหัน, ยาวผิดปกติ = คิดเยอะ/ไม่กล้าตัดสินใจ | 🔴 เดา — ต้องเทียบกับค่าเฉลี่ยของ *ตัวผู้ใช้เอง* ไม่ใช่ค่าเฉลี่ยคนทั้งเว็บ |
| **ดูคลิป/อ่านจนจบ vs ข้ามกลางคัน** | ความอดทน, ความใส่ใจรายละเอียด | 🟡 กลาง |
| **กด replay ซ้ำ** | อยากเข้าใจให้ครบ (O สูง / C สูง) | 🔴 เดา |
| **scroll ถึงท้ายบทความไหม** | อ่านจริงหรือกดผ่าน | 🟢 สูง (วัดตรงไปตรงมา) |
| **ความสม่ำเสมอของเวลาต่อข้อ** | สมาธิ, ความเหนื่อยล้าท้ายแบบทดสอบ | 🟡 กลาง |
| ⭐ **เปลี่ยนคำตอบหลังเห็น feedback** | สัญญาณ growth mindset — ปรับตัวจากข้อมูลใหม่ | 🟡 กลาง (แต่ตรงคอนเซปต์ที่สุด) |
| **ตอบแบบเดียวกันรัว ๆ (straight-lining)** | ตอบมั่ว → ต้องตัดข้อมูลทิ้ง ไม่ใช่ตีความ | 🟢 สูง |

### ⚠️ คำเตือนที่ต้องเขียนไว้ให้ตัวเองในอนาคต

สัญญาณพวกนี้ฟังดูฉลาด แต่**ยังไม่มีใครพิสูจน์ว่าจริง** ก่อนจะเอาไปคิดคะแนนหนัก ๆ ต้องทำ Phase 2 (เก็บข้อมูลจริงเทียบกับแบบวัดมาตรฐาน) ก่อน

จนกว่าจะพิสูจน์ได้ ให้แสดงเป็น **"ข้อสังเกต"** ไม่ใช่ **"ผลการวัด"**
เช่น *"เราสังเกตว่าคุณย้อนกลับไปแก้ข้อ 2 ถึง 3 ครั้ง"* (ข้อเท็จจริง ✅)
ไม่ใช่ *"คุณมีความวิตกกังวลระดับสูง"* (การตีความที่ยังพิสูจน์ไม่ได้ ❌)


### Event — ⭐ หัวใจของระบบ (append-only log)

```json
{
  "sessionId": "s_8f3a...",
  "seq": 42,
  "itemId": "q_c_plan_01",
  "kind": "answer_change",
  "t": 1724500000123,
  "payload": { "from": "b", "to": "a", "visitNumber": 2 }
}
```

`kind` ที่ต้องมี:
`item_view` · `first_input` · `answer` · `answer_change` · `skip` · `back` · `revisit` ·
`media_start` · `media_progress` · `media_complete` · `media_skip` · `replay` ·
`scroll_depth` · `feedback_shown` · `feedback_response` · `session_end`

> **หลักการสำคัญ:** เก็บ event ดิบไว้ก่อน อย่าตีความตอนเก็บ
> วันนี้เราคิดว่า "ข้าม = หลีกเลี่ยง" แต่ปีหน้าอาจพบว่าไม่ใช่ — ถ้าเก็บดิบไว้ ก็คำนวณใหม่ย้อนหลังได้ทั้งหมด ถ้าเก็บแต่ผลตีความ ข้อมูลเก่าจะใช้ไม่ได้เลย

## 7️⃣ การให้คะแนนและรายงานผล

### กฎเหล็ก: แยกสองสายให้ขาดจากกัน

```
สาย A: คะแนนจากคำตอบ  →  แถบ Big Five + เข็ม growth/fixed   [เชื่อถือได้ระดับหนึ่ง]
สาย B: สัญญาณพฤติกรรม  →  กล่อง "ข้อสังเกต"                    [เป็นข้อสังเกต ไม่ใช่คะแนน]
```

**ห้ามยุบสองสายเป็นตัวเลขเดียว** — เพราะความน่าเชื่อถือต่างกันคนละชั้น

### หน้ารายงานควรมี

1. 📊 แถบ Big Five 5 แกน + คำอธิบายแบบไม่ตัดสิน (ไม่มีปลายไหน "ดีกว่า")
2. 🧭 เข็ม growth ↔ fixed
3. 👁️ **"สิ่งที่เราสังเกตจากพฤติกรรมของคุณ"** 3–5 ข้อ — *อันนี้แหละที่ทำให้คนอยากจ่าย*
4. 🗺️ **แผนที่เส้นทางที่คุณเดิน** — โชว์กิ่งที่เดินจริงบน mind-map พร้อมกิ่งที่ไม่ได้เดิน (คนจะอยากทำใหม่เพื่อดูกิ่งอื่น = viral loop)
5. ⚖️ ระดับความมั่นใจของแต่ละแกน + บอกตรง ๆ ว่าแกนไหนข้อมูลไม่พอ
6. 📜 ปุ่มดู event log ดิบของตัวเอง (โปร่งใส = ความไว้ใจ = คนกล้าจ่าย)

## 8️⃣ สถาปัตยกรรมถ้าจะทำจริง

```
[Browser]  React/Next + XState (state machine)
    │  ยิง event เป็น batch ทุก 2-3 วิ (ไม่ยิงทีละ event)
    ▼
[API]  POST /session  ·  POST /events  ·  GET /next-item  ·  GET /result
    │  ⭐ เลือกข้อถัดไป "ฝั่งเซิร์ฟเวอร์" เท่านั้น
    ▼
[DB]  sessions · events (append-only) · items · results · payments
```

### ทำไมต้องคำนวณข้อถัดไปฝั่งเซิร์ฟเวอร์

- ถ้าส่ง item pool ทั้งก้อนไปที่ browser → เปิด DevTools ก็เห็นคำถามทั้งหมด + น้ำหนักคะแนนทุกข้อ → คนแกะได้ว่าตอบยังไงให้ได้ผลที่ต้องการ → เว็บตายทันที
- ส่งไปทีละข้อเท่านั้น

### สิ่งที่ต้องกัน

| ปัญหา | วิธีกัน |
|-------|--------|
| bot / คนกดรัวเพื่อดูผล | rate limit + ตรวจ straight-lining + ตรวจเวลาต่อข้อต่ำผิดปกติ |
| คนทำซ้ำเพื่อไล่ดูทุกกิ่ง | ไม่ต้องกันหมด — ให้ทำซ้ำได้แต่จำกัดต่อวัน (การอยากดูกิ่งอื่นคือแรงดึงของเว็บ) |
| ข้อมูลรั่ว | event log มีข้อมูลพฤติกรรมละเอียด = ข้อมูลอ่อนไหว ต้องเข้ารหัส at rest |

### ระบบจ่ายเงิน

- ไทย: **PromptPay QR** (Omise / GB Prime Pay / Stripe รองรับแล้ว) — คนไทยจ่ายง่ายที่สุด
- ต่างประเทศ: Stripe
- pay-what-you-want ต้องกำหนดขั้นต่ำ (ค่าธรรมเนียมจะกินหมดถ้าต่ำกว่า ~20 บาท)
